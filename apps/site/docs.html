Self-host with Docker

This is the complete product: accounts, sync, coaching, and the PWA people install on their phones. You need Docker with the Compose plugin. No local Node — the images build the app for you.

git clone <your-repo> gymbuddy
cd gymbuddy
cp .env.example .env
docker compose up -d --build

Open http://localhost:8080 and create a profile. The first start downloads the exercise images and animations (~140 MB) once, migrates the schema, and seeds the 1,324-exercise library.

Three containers and a database volume: nginx serves the built app and proxies /api, so everything is one origin — which is what passkeys require. The API is internal only. Postgres holds every account and every set ever logged; docker compose down leaves the volume alone, down -v destroys it.

With SEED_DEMO=1 — the default in .env.example — the first boot also creates a demo coach and three clients with twelve weeks of training each, so you can see the coaching screens with something in them. Turn it off for a real instance, and set a real SESSION_SECRET.
Want it reachable from your phone with passkeys? You need an HTTPS domain, and passkeys are bound to the exact hostname. The full guide — reverse proxy, backups, invite-only signup, and the AI provider settings — is docs/SELF_HOSTING.md in the repository.

Connect a coach to a client

Coaching lives entirely in the web app. Both people need an account on the same instance.

  1. The coach invites the client, and the client accepts. Nothing happens until they do.
  2. The client chooses scopes — which sections the coach may read. Programmes, workouts and body weight are separate choices, and any of them can be withdrawn later.
  3. The coach drafts a programme and sends it. It arrives as a proposal.
  4. The client accepts it, and only then is it written — as the client's own data, through the same sync path their phone uses.
A coach never writes a client's rows. That is a property of the schema, not a promise in a settings screen: there is exactly one writer per row, so a coach's edit cannot erase a client's, and a lapsed subscription cannot take a client's training away. See About for why the fork exists at all.

On an instance with a payment provider configured, the coach side is a subscription — it gates taking on new clients, proposing programmes, and messaging. Reading a roster you already built is never gated, and a client is never gated at all. With no provider configured, coaching is simply free. See pricing.

Use on iPhone

Open your GymBuddy instance in Safari, then Share → Add to Home Screen. You get a full-screen app with its own icon, passkey sign-in, sync and all of the coaching — no expiry, no fees, no store.

This is not a consolation prize: the PWA is the complete product, and the native builds are the cut-down offline ones. The best iPhone experience here is the one that involves no app install at all.

Install on Android

The Android app is the offline tracker — no accounts, no sync, no coaching, nothing to buy. If you want coaching on Android, install the PWA from your instance the same way iPhone does it (Chrome → menu → Install app).

  1. Download the signed APK on your phone, or install from Cafe Bazaar or Myket.
  2. For the direct APK, your browser will ask whether it may install apps — allow it. This is standard for anything installed outside a store, and the permission can be revoked immediately afterwards.
  3. Open it and start logging. There is no account step, because there is no account.

Training data lives in a file in the app's private storage. The only thing fetched from the network is the exercise media.

Import your training history

Coming from another tracker? Settings → Data → Import from another app reads:

  • FitNotes (both the Android and the FitNotes 2 iOS export)
  • Strong and Hevy (CSV exports — session lengths carry over, so the activity heatmap fills in properly)
  • Apple Health (body-weight history from the XML export)
  • …and anything else with date, exercise-name and weight/reps columns

Exercise names are matched against the 1,324-exercise library; anything genuinely ambiguous becomes one of your own custom exercises instead of being guessed at. A summary shows exactly what will happen before anything is written, and importing is idempotent — running it twice never duplicates a workout.

Backups

Settings → Data → Export backup (JSON) writes your entire log — plan, workouts, weights, settings — into one file. On the Android app it goes out through the share sheet; in the browser it downloads. Import backup restores it anywhere: another phone, your self-hosted instance, or a fresh install.

If you run the server, back up the Postgres volume too — that is where every account and every set actually lives. The per-user export is a user's copy of their own data, not an instance backup.

Build it yourself

  • Web / self-host: docker compose up -d --build builds everything inside the containers.
  • From source: npm install, then npm run db:reset, npm run api and npm run dev. npm test runs the domain, database, API, client and release suites; the database ones need a Postgres in DATABASE_URL.
  • Android APK: npm run sync:mobile then Gradle's assembleRelease. Signing and distribution notes are in docs/RELEASING.md.
After npm run sync:mobile the client's dist/ holds the mobile bundle — the one with no sign-in. Deploying that to a server ships an accountless app to everyone who visits. Build the web app with npm run build.

FAQ

Is it free?

The software is free as in cost and as in freedom (AGPL-3.0), and training is free in every deployment. On a hosted instance that charges, the only thing a subscription gates is a coach taking on new clients, proposing programmes and messaging them — never a client, and never anyone's training log. Self-host with no payment provider and coaching is free too.

What data does GymBuddy collect?

None. There is no telemetry, no analytics and no crash reporting. A self-hosted instance talks only to your own server; the Android app talks to no server at all.

Does the AI see my training?

Only if a model is configured, and only for the two jobs it has: parsing free text into a structured brief, and writing the note that explains a change. Every number is computed locally by the app's own planner. Configure no model and everything still works — plans, stall detection, log parsing — phrased from a template instead of written as prose. You can also point it at a model on your own hardware and nothing leaves the building.

Why isn't it on the Play Store or the App Store?

Because the Apple Developer Program and the Google Play Console are not available to Iranian developers or Iranian companies — US sanctions, no Iranian App Store storefront, and Play is not usefully reachable from Iran either. That is not a step that was skipped; it is not a step that exists on this path. What is left is the direct APK, the Iranian Android stores (Cafe Bazaar and Myket), and — for iPhone — the PWA, which is the fuller product anyway.

Where does the exercise database come from?

The names and instructions come from the hasaneyldrm/exercises-dataset project. The images and animations are © Gym visual and are not covered by GymBuddy's licence — they are downloaded from the upstream source on first run rather than redistributed here, and they are not ours to sublicense. A commercial deployment needs its own licence for them, or its own artwork; exercise rows carry the media URLs, so swapping the source is a database update. Full details are in the project's NOTICE.md.

Can I use my own model provider?

Yes. Anything speaking the OpenAI request shape is one adapter, and a local model is supported as the failover underneath it. Two tiers are configurable, because the note a client actually reads is worth a better model than the parse nobody sees. See .env.example.

I used openGym. Can I bring my data?

Yes. GymBuddy stores the same training in a relational schema instead of one JSON document, and the code that turns an openGym state file into rows lives in the project rather than in a one-off script — the demo seeder runs through it too, so the migration is exercised on every seed. For a single account, an openGym backup file goes in through Settings → Data → Import backup.
